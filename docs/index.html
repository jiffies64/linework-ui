05 — The rule

A drawing should read before it is used.

01

Every line has a job.

Hairlines separate. Heavy rules define. Dashed lines mean construction or focus. Nothing is a shadow pretending to be structure.

02

Redline means live.

Playing, recording, destructive, focused. If it is red, something is happening. It is never decoration, and it never means “on brand”.

03

Tokens all the way down.

Paper, ink, rule, redline, spacing, motion. Override the values and every component follows.

06 — Install

Two files. Then start copying.

Start with one sheet.

No package manager required. If you bundle, the package exports are ready. Link the CSS, load the behaviour, and write plain markup. React, Vue, Svelte, Astro and plain HTML all work.

1

Link the sheet

The full system is one CSS file: tokens, layout and all components. Use the minified build in production.

2

Load the behaviour

Only the interactive parts: drawers, tabs, pads, meters, toasts. Everything degrades to sensible HTML without it.

3

Pick a paper

Trace by default. Set data-theme on the root for blueprint or vellum, or override any token.

07 — Notes

Short answers, on the drawing.

Questions from the site.

Do I need React, Tailwind or a build step?

No. The library is plain CSS and JavaScript. You can copy a block into an HTML file and open it. If you do use React, Vue, Svelte or Astro, the classes work as-is and the eight Web Components are standard custom elements. React also gets typed wrappers from linework-ui/react.

How do the blocks stay reusable once I paste them?

Blocks are built from documented components rather than one-off styles. Shared structure lives in classes like lw-btn, lw-plate and lw-titleblock; the block file only adds layout.

Can I use my own brand colours?

Yes. Every colour is a token (--lw-ink, --lw-redline, --lw-paper). Override them in a theme block or on any container. The three papers are examples.

Is it accessible, or just visually sharp?

Native controls underneath, visible focus rings drawn as dashed construction lines, keyboard support in tabs and drawers, reduced-motion handling, and AA-contrast text in all three papers. Accessibility notes are part of the documentation.

Is there a complete application example?

Yes, the project console. It is a full app shell with a schedule, approvals, menus, three drawers and a working create-sheet form, built from the same two library files as this page.
